# dsh Jev 自动模型路由插件

Status: ready-for-agent

日期：2026-09-22。依据本次设计讨论与现有 dsh 代码调查整理，作为本地 issue tracker 中该功能的正式规格。本文取代前一版待确认草案；发布规格不表示实现、安装或真实模型验证已经完成。

## Problem Statement

用户已运行 DeepSeek Harness，希望针对任务所需能力自动选择模型，减少手动切换，并在质量足够的前提下降低费用与等待时间。只看当前一句话无法可靠判断任务：例如“继续”可能承接复杂改造，而长输入也可能只是简单转换。

频繁切换模型会增加上下文重新计算的成本，尤其是在长对话和工具调用任务中。同一提供商的不同模型不能假定共享 KV cache，已有缓存命中也不能保证下一次仍命中。用户需要能理解并控制的切换规则，包括上下文阈值、保留当前模型的条件、手动覆盖和插件开关。

参考项目已利用 Jev、缓存证据和路由复用，但其 Codex 集成方式、固定模型梯队、额度回退与观察模式不适合直接搬到本项目。dsh 插件需要与现有会话、模型选择、设置、凭据和工具执行机制一致。

## Solution

提供可独立安装到当前 dsh Web profile 的插件，包含服务端路由与设置界面。插件仅有开启和关闭两种状态；开启后，对选择 Auto 的主会话直接执行自动路由；关闭后不调用 Jev、不干预原有模型选择。手动固定模型始终优先。

每个由用户输入开始的 turn 至多判断一次。Jev 接收当前问题、有限相关上下文以及候选模型与缓存证据，分别判断需要的能力和思考深度。插件验证结果并应用用户设置，同一 turn 的后续工具 step 保持实际选定路线。执行模型继续收到 dsh 正常构建的完整有效上下文。

质量优先，缓存和成本用于选择足够胜任的路线。默认完整输入超过 32,768 tokens 时只允许必要升级；用户可修改阈值、禁用阈值，或改为超限保持模型。提供分类超时回退、路由结果展示及用量记录。

首批验证 `ctapi/deepseek-v4-flash-vip` 与 `ctapi/deepseek-v4-pro-vip`。配置结构允许后续扩展提供商，但本规格不把未经验证的网关能力当成既有事实。

## User Stories

1. 作为 dsh 用户，我希望安装独立插件，以便在现有运行环境中获得自动模型路由。
2. 作为 dsh 用户，我希望插件只有开启和关闭两种状态，以便直接理解它是否在工作。
3. 作为 dsh 用户，我希望开启后实际应用路由决定，以便无需经过观察模式。
4. 作为 dsh 用户，我希望关闭后完全不调用 Jev，以便停止分类费用与自动干预。
5. 作为 dsh 用户，我希望在设置页面修改并保存配置，以便无需手工修改源码。
6. 作为 dsh 用户，我希望常用项与高级项分开展示，以便快速完成基本配置。
7. 作为 dsh 用户，我希望配置错误能明确显示且不部分生效，以便知道实际使用的设置。
8. 作为 dsh 用户，我希望从已接入的模型中指定候选，以便控制自动路由可以选择的范围。
9. 作为 dsh 用户，我希望候选模型有明确的能力定位，以便理解什么情况属于升级或降级。
10. 作为 dsh 用户，我希望首先验证当前已有的两款 ctapi DeepSeek 模型，以便尽快建立可用的运行基线。
11. 作为 dsh 用户，我希望指定默认回退模型，以便首次分类失败时仍能继续任务。
12. 作为主会话用户，我希望选择 Auto 后由插件判断模型，以便减少逐轮手动选择。
13. 作为主会话用户，我希望随时手动固定模型，以便让明确的个人选择优先于自动建议。
14. 作为主会话用户，我希望固定模型后必须主动切回 Auto 才恢复路由，以便插件不覆盖我的选择。
15. 作为已有会话的用户，我希望安装或开启插件不接管原来的模型选择，以便保留现有工作方式。
16. 作为新会话的用户，我希望在插件已开启时继承自动路由设置，以便减少重复操作。
17. 作为同时使用多个会话的用户，我希望各会话的路线和缓存证据互相隔离，以便一处切换不影响另一处。
18. 作为使用子 Agent 的用户，我希望首版保留其原有选模行为，以便不意外改变委派任务。
19. 作为使用 fork 的用户，我希望普通分支会话仍可使用 Auto，以便不被误认为子 Agent。
20. 作为执行工具任务的用户，我希望每个用户 turn 只分类一次，以便控制额外延迟与费用。
21. 作为执行工具任务的用户，我希望同一 turn 的工具续步保持模型和思考设置，以便避免执行期间频繁切换。
22. 作为会话用户，我希望简短追问能结合相关任务上下文判断，以便“继续”不会被误判为简单任务。
23. 作为会话用户，我希望限制发给 Jev 的材料长度，以便控制分类开销和发送范围。
24. 作为会话用户，我希望知道分类材料会发送到 TypeSafe，以便理解插件的数据流向。
25. 作为会话用户，我希望执行模型保留完整有效历史，以便路由优化不造成任务信息丢失。
26. 作为长对话用户，我希望设置允许普通切换的上下文上限，以便限制昂贵的上下文重新计算。
27. 作为长对话用户，我希望选择超限保持模型或仅允许升级，以便在缓存成本与能力需求之间设置自己的规则。
28. 作为长对话用户，我希望能够禁用上下文阈值，以便按自己的工作负载调整路由。
29. 作为长对话用户，我希望阈值依据完整请求规模且估算值有标识，以便不被单条消息长度或累计账单误导。
30. 作为会话用户，我希望切换后保持若干完整用户回合，以便减少模型来回切换。
31. 作为复杂任务用户，我希望默认的保持规则不阻止必要升级，以便缓存优化不限制任务能力。
32. 作为会话用户，我希望使用实际缓存证据辅助判断，以便优先复用能够胜任的当前模型。
33. 作为会话用户，我希望缺失缓存数据被标记为未知，以便不把网关未报告误认为零命中。
34. 作为会话用户，我希望可选择是否自动调整思考强度，以便控制推理开销。
35. 作为会话用户，我希望只能使用网关真实支持的思考档位，以便不会发送不受支持的参数。
36. 作为会话用户，我希望 Jev 超时或回答无效时沿用有效路线，以便分类服务不阻断正常工作。
37. 作为会话用户，我希望执行模型报错时保留 dsh 原有恢复机制，以便不重复已执行的工具操作。
38. 作为会话用户，我希望取消或关闭插件后迟到的分类结果不再生效，以便控制状态可靠。
39. 作为会话用户，我希望普通设置变更从下一回合生效，以便当前工具链行为保持稳定。
40. 作为会话用户，我希望看到建议模型、实际模型和未切换原因，以便判断是分类结果还是配置规则影响了选择。
41. 作为会话用户，我希望可以独立关闭路由展示和指标记录，以便调整界面与诊断需求。
42. 作为配置凭据的用户，我希望沿用 dsh 的凭据管理，以便密钥不进入普通设置或诊断日志。
43. 作为费用敏感的用户，我希望费用数据缺失时明确显示未知，以便不把推测当成已实现的节省。
44. 作为评估插件的用户，我希望比较自动路由与固定 Pro 的任务完成情况、缓存、用量和延迟，以便判断路由是否值得启用。
45. 作为插件维护者，我希望加载、卸载与热更新能完整清理贡献和请求，以便没有重复分类或残留监听。
46. 作为插件维护者，我希望通过真实 dsh 组合验证模型选择与会话记录一致，以便避免单元测试通过但实际产品不可用。
47. 作为插件维护者，我希望候选能力与调用价格的不确定性被明确记录，以便后续扩展不依赖未经证实的假设。

## Implementation Decisions

### 集成与职责

1. 交付独立 Cordis 插件的 Host 与 Client 入口，优先使用现有扩展点，不修改 dsh 主循环或建立额外转发代理。
2. Host 拥有配置解析、Jev 通信、回合路线、切换约束与指标；Client 拥有设置卡片、Auto/固定选择交互及路由结果展示。内部策略逻辑保持私有，不为测试创建新的生产服务层。
3. 使用现有 settings namespace 持久化 `jev-router` 配置，使用设置卡片 slot 和 settings scope 同步客户端。沿用现有配置版本冲突、保存失败和重新读取行为。
4. Jev 密钥通过 credentials 引用解析，普通设置仅保存引用；输入新密钥使用既有凭据写入能力，既有密钥不作为普通配置值返回客户端。
5. 模型目录、输入模态、上下文窗口和推理档位来自现有 LLM 服务。插件自动路由不能调用会顺带更新全局默认模型的会话命令作为无副作用 setter。
6. 利用 inbox 接收、system prompt assembly 与 request 扩展点协调选模。当前 dsh 在 pre-step 前已组装系统提示，因此不能只在 pre-step 更新选模引用。具体组合必须使提示中的模型信息、真实请求、切换通知及会话日志一致，并保留 waterfall 委派与卸载契约。
7. 所有执行模型可见内容沿用 dsh 的可重建日志通道；不在已冻结请求上修改模型，不把展示用原因或诊断指标加入稳定的提示前缀。任何必要的模型切换通知也必须可从会话记录重建。

### 用户控制与生命周期

8. `enabled` 是唯一的插件状态字段。首次安装默认关闭；开启时直接执行决策，没有观察、试运行或只判断不应用的产品模式。
9. Auto/固定是会话模型选择，不是第三种插件状态。开启时新建主会话默认 Auto；已有会话保持原选择，用户主动切入才接管。保存会话选择，恢复后不覆盖用户固定状态。
10. 手动选择始终优先。插件不能改变其他会话或全局默认模型。子 Agent 依持久化 origin 排除，普通 fork 不能仅因有父会话而被排除。
11. 用户回合指以用户输入开始的一次 turn；一次接收批次的输入共同参与一次判断。一个 turn 可包含多个 step，step 是模型请求及它引起的工具执行。工具续步与请求重试不重复调用 Jev。
12. 每个 turn 开始快照配置并最多分类一次，固定其模型与思考设置。普通设置变更在下一用户 turn 生效。用户明确关闭或手动覆盖属于例外：取消未生效的分类，已发出的请求正常结束，后续请求服从用户选择且不重跑工具。
13. 用户取消、会话销毁、插件卸载须取消未完成请求。应用决定时核对其所属会话、turn 和当前控制状态，拒绝迟到结果。会话状态互相隔离。
14. 冷启动恢复已开始的 turn 时沿用 dsh 已记录的实际路线，不因内存分类记录丢失而再次分类；保持回合计数可依据持久化的实际路线与已完成 turn 重建。不可确认的缓存证据恢复为未知。

### 配置契约与默认值

15. 保留已讨论的以下设置。32K、两个回合、两秒和材料预算均为可调初始值，不宣称为已测得的最优值。

| 字段 | 默认值或初始化方式 | 语义 |
| --- | --- | --- |
| `enabled` | `false` | 插件总开关 |
| `candidateModels` | 首批两款 ctapi 路线 | 用户选择的 provider/model、能力描述与明确档位 |
| `defaultModel` | 初始化时选定的 dsh 默认模型 | 首次无当前有效路线且分类失败时使用，不反向更改 dsh 默认模型 |
| `routeReasoning` | `true` | 仅调整运行时确认支持的思考档位 |
| `switchContextLimitTokens` | `32768`，`null` 表示禁用 | 完整输入规模的自由切换上限 |
| `overLimitPolicy` | `upgrade_only` | 可选 `keep`，分别表示超限只允许升级或不切模型 |
| `minHoldUserTurns` | `2`，`0` 表示禁用 | 切换后保持的已完成用户回合数，不阻止必要升级 |
| `cacheAware` | `true` | 使用实际缓存证据辅助判断 |
| `jevTimeoutMs` | `2000` | 单次分类总等待上限，超时终止并回退 |
| `jevMaxStateChars` | `6000` | 序列化分类 state 的 Unicode 字符预算，包含其中字段名与结构，不限制执行上下文 |
| `showDecision` | `true` | 显示建议、执行路线及规则原因 |
| `recordMetrics` | `true` | 记录结构化决策与用量，不默认记录对话原文 |
| `apiKeyEnv` | 用户选择或创建的凭据引用 | 通过 dsh 凭据服务解析 |

16. 常用项直接展示；保持回合数、分类超时与材料预算放入高级设置。遵循 dsh 现有本地化方式提供用户文案。
17. 配置在输入边界校验：拒绝重复候选、无法解析的路线、无效数值以及显式指定但不支持的推理档位。阈值是正整数或禁用值，保持回合数是非负整数，超时和材料预算是有效正整数。预算无法容纳最低限度的有效分类材料时明确报错，不静默超限。
18. 首批 Flash 为经济档，Pro 为较高能力档。这是可调先验而非实测保证；不得仅根据名称或价格推断其他模型之间的升级关系。候选限制成功自动选模；发生分类故障时允许沿用会话当前路线或用户配置的默认回退路线，并标明这是回退。

### Jev 通信与上下文

19. 使用 TypeSafe 的 System One API、Bearer 凭据和 `jev-latest`，发送结构化 state 与独立 Choice 问题，分别判断所需能力与思考深度。供应商返回的实际 Jev 版本在可用时记录，便于结果比较。
20. state 包含当前输入、有限相关任务上下文、候选能力描述和可用缓存证据。上下文依赖的短回复包含前一任务或相关助手提议；必要时包含有限代码或工具结果片段。设置页说明这些材料会发送到 TypeSafe。
21. 分类材料是证据，不是配置指令；其中的引用内容不能更改候选白名单或绕过用户规则。只接纳符合请求契约的结构化选项，不通过任意文本猜测结果。
22. 只在真实支持的范围内映射思考强度，不照搬 Codex 或 DeepSeek 原生端点的固定枚举。没有可用思考档位时仍可路由模型，保留适配器默认行为并显示该能力不可用。
23. 限制应用于完整序列化 state，保留当前输入与相关任务证据，截断必须可识别。执行模型不使用该截断 state 代替历史，继续接收 dsh 正常构建的完整有效上下文。正常上下文压缩仍由 dsh 管理。

### 规则顺序与缓存

24. 先检查启停、会话范围和手动选择，再检查候选兼容性、获取有效分类、应用用户切换限制并确定实际路线。无合法选项时不向 Jev 提交空选项问题。
25. 输入规模包括系统提示、工具定义、历史和工具结果；不使用当前一句话长度或会话累计 token 消耗。结合 dsh 可用估算与最近用量，标记估算属性；不同模型 tokenizer 的差异不能被宣称为精确计数。无法可靠估算时不为省钱而降级。
26. 输入规模大于阈值才触发超限策略；等于阈值仍允许普通切换。`keep` 阻止模型切换，`upgrade_only` 只放行明确的必要升级。禁用阈值不施加该限制。
27. 切换当回合完成后计为第一个保持回合，下一个完整用户回合计为第二个，默认第三个回合开始可降级。取消、失败和仅工具 step 不计完成回合。保持限制不阻止必要升级；不明确的档位关系不作为升级放行。
28. 首次没有可比较的已选路线时正常选择兼容候选；已有路线在约束生效而缺少可比较档位时保留有效路线并说明原因。规则禁止切换时仍可在该模型支持范围内调整思考强度。
29. 缓存证据按会话与具体 provider/model 保存，使用实际缓存读取、未缓存输入和证据时间；缺失字段记为未知，不当作零。上下文发生不兼容变化时旧证据不再被当作当前前缀的命中证明。
30. 缓存只影响足够胜任的路线选择，不强制把困难任务留在弱模型。`cacheAware=false` 时移除缓存软偏好，用户设置的长度和保持约束仍有效。同供应商与相同 cache key 都不能证明跨模型 KV cache 共享。
31. 模型真实窗口与输入模态是独立兼容性要求，需为输出留出合理空间。未知窗口不等于无限。目标无法容纳请求时不自动选择它，不为达成切换额外裁剪历史；没有兼容候选时沿用可用原路径或明确报告不能路由。

### 故障、展示与记录

32. 缺凭据、分类超时、服务失败或响应不合法时沿用当前有效模型；没有当前有效模型时使用配置的默认模型。都不可用时显示可操作错误，不擅自找另一提供商。取消不是服务故障，不能触发新的执行。
33. Jev 分类故障与低置信度不是同一件事，不设低置信度强制升级规则。回退应显示原因；输出校验失败不能部分应用模型或思考设置。
34. 执行模型失败沿用 dsh 的请求重试与错误处理，不自动跨模型重跑整个 turn，不重复已经完成的工具操作。用户可手动换模型后继续。
35. 展示建议路线、实际路线、思考设置和可核实原因，例如超限保留或分类超时回退；不编造 Jev 未返回的解释。显示数据以实际已采用的决定为准，不提前把候选建议标成已执行。
36. 记录策略版本、分类耗时、建议与实际路线、规则原因、回退状态和可用 token/cache 用量。沿用 dsh 对未缓存输入、缓存读取与写入的计数语义，避免重复计算。指标记录与路由所需的短期缓存证据是不同职责，关闭诊断记录不改变路由。
37. 凭据与对话原文不默认进入诊断记录。缺失费用或缓存字段明确标未知；仅在获得可信价格和用量时计算费用，不把模型分布、分类置信度或单价差冒充已实现的节省。
38. 注册设置、UI 和事件监听必须可卸载。热更新销毁旧贡献和未完成请求，不重复路由，不修改当前实例已有的全局默认模型。

## Testing Decisions

1. **主要测试边界是现有 dsh Web profile／Loader 的真实插件组合。** 从用户输入、会话模型选择或设置操作进入，观察出站模型请求、持久化会话日志、配置保存与界面结果。路由 Host、现有选择器、会话、工具执行、settings 和凭据交互保留真实实现；测试不新增生产级测试接口。
2. **只有外部或非确定性边界使用替身。** 自动化中替换 Jev 网络、模型供应商网络与必要的时钟；用真实 Loader 加载测试组合，而不是把内部回调单独拼起来就宣称完成集成。少量纯规则边界用例可以使用同一公开行为入口或私有内部函数，但不成为唯一验收证据。
3. **好测试验证可观察行为。** 不断言私有方法名、内部字段布局或仅复述实现的调用顺序；应断言实际模型收到什么、日志记录了什么、用户看到什么，以及禁止路径没有发请求或产生工具副作用。取消与卸载用例验证迟到结果无法提交，不仅验证调用过 abort。
4. **测试对象包括插件整体的路由、设置与凭据接入、会话控制、故障回退、缓存计量和路由展示。** 浏览器使用真实设置组件与应用壳验证编辑、保存、刷新、错误反馈和 Auto/固定行为；沿用现有 Client 测试基础设施补充必要的可见状态断言。
5. **沿用已有先例。** settings-file 已有通过 Loader 与 Include 加载真实设置消费者、验证文件变更和配置回退的组合测试；agent 已有模型选择快照、请求路线、切换通知及卸载测试；ui-settings-plugins 已有设置卡片注册、Host namespace 响应与卸载测试。agent-loop 的请求冻结、重建、取消和恢复测试可指导日志一致性与中断验证；这些先例不代替本插件的完整组合场景。
6. **覆盖状态与作用范围。** 关闭零 Jev 调用，开启直接路由，无观察分支；已有会话保留、新会话继承、手动固定优先、普通 fork 可用、子 Agent 排除、并发会话隔离以及不修改全局默认模型。
7. **覆盖回合与竞态。** 同一 turn 多工具 step 只分类一次，供应商重试不重分类；分类期间关闭、手动固定、取消、设置变更和卸载均不能应用过期决定。恢复 turn 保留路线，热更新不重复注册。
8. **覆盖约束边界。** 阈值下方、恰好阈值、超过阈值、禁用阈值、未知规模，两种超限策略，默认两个已完成回合保持、取消不计数、必要升级例外和未知档位不可冒充升级。
9. **覆盖数据与能力契约。** 短追问具有相关上下文；中英文及超长输入的完整序列化材料符合预算；分类截断不影响执行历史；不兼容上下文、模态和思考档位被拒绝或明确回退，不靠静默截断“成功”。
10. **覆盖故障的实际后果。** 超时、无效 JSON／选项、认证或服务错误、无有效候选和无回退路线；执行请求在输出前后失败时，不发生跨模型整轮重跑或重复工具操作。原有重试、日志及 UI 错误保持一致。
11. **覆盖指标与界面。** 实际缓存命中、未命中、字段缺失和陈旧证据分别可辨；计数不重复；展示与记录开关独立；无可信价格时不输出虚假节省；凭据不通过普通设置读回或诊断暴露。
12. **增加无密钥会话回放场景。** 至少包含路由切换和工具续步、阈值阻止切换、Jev 故障回退，比较最终持久化会话与用户可见路由。Web 场景保留浏览器可访问性或界面证据，与实际会话对应。
13. **真实集成单独验收。** 两条 ctapi 路线分别验证基本生成、工具调用、实际思考档位和 usage；从已安装插件的 dsh profile 发起小规模 Jev 路由验证。缺凭据或网关不可用时明确标注未验证，不用 mock 成功替代，也不要求单次真实调用必定缓存命中。
14. **效果评估使用同一组任务与完成标准。** 对固定 Pro 和自动路由分别执行常规任务、复杂任务、短追问与长上下文场景，记录任务是否完成、修正次数、分类开销、用量、缓存及延迟。有可信价格时纳入 Jev 与全部重试成本；区分冷暖缓存条件，不以模型占比作为质量或节省目标。小样本只支持有限结论。
15. **执行适用的工程检查。** 插件类型、构建、配置及包导出检查需通过；组合测试管理自己的端口、临时文件与进程并完整清理，可并行运行。界面按现有本地化与插件卸载约定验证。

## Out of Scope

- 观察、shadow 或只分类不执行的产品模式。
- 每次模型请求或每个工具 step 重新分类、自动中途改变模型。
- 子 Agent 自动路由，以及全量支持所有 dsh profile、供应商和模型的承诺。
- 为切模型额外压缩历史、摘要交接或裁剪执行上下文。
- 跨模型 KV cache 迁移、保证缓存命中或依靠同提供商推断缓存共享。
- Codex Router 转发层、Codex 原生额度共享与额度耗尽后的外部供应商发现。
- 强制使用特定最高档模型的任务关键词规则、目标模型分布或低置信度自动升级。
- 执行模型故障后的自动跨模型重跑、自动重复工具操作。
- 独立任务拆分路由、额外审阅 Agent 或质量评分纠正循环。
- 首版的故障熔断配置、可编辑价格表与最低节省比例、可调缓存证据有效期。
- 未经效果评估即宣称等质量省费或确定的收益百分比。
