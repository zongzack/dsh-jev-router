# 02 — 提供长上下文与缓存切换保护

**What to build:** 用户可在设置页限制长上下文下的模型切换，控制切换后保持多少个完整回合，以及是否使用实际缓存证据辅助判断。设置真实影响 Jev 路由的最终执行结果；当建议被规则拦截时，用户能看到保留当前模型的具体原因。该路径从设置保存贯通上下文计量、选模约束、实际请求和解释展示。

**Blocked by:** 01 — 跑通可安装的逐回合自动路由。

**Status:** ready-for-agent

**Parent:** 《dsh Jev 自动模型路由插件》正式规格。主要覆盖用户故事 9、25–33、39–40、47；完整指标记录和真实收益比较归 04。

## Acceptance criteria

- [ ] 设置页提供并持久化 `switchContextLimitTokens`、`overLimitPolicy`、`minHoldUserTurns` 与 `cacheAware`。默认依次为 32,768、`upgrade_only`、2、开启；阈值以 `null` 禁用，保持回合数以 0 禁用。
- [ ] 阈值必须为正整数或禁用值，保持回合数为非负整数；非法设置有明确反馈且不部分生效。普通配置每个用户 turn 开始快照，执行中修改不改变当前工具链。
- [ ] 判断依据是本次完整输入规模，包括系统提示、工具定义、历史与工具结果；不使用当前单条用户输入长度或会话累计 token 消耗。估算值明确标识，不将不同 tokenizer 下的估算宣称为精确值。
- [ ] 无法可靠估算输入时，不因省钱而降级；界面显示信息不足的原因，不宣称当前输入低于阈值。
- [ ] 大于阈值时才执行超限限制，等于阈值仍允许普通切换；`keep` 保持模型，`upgrade_only` 仅允许明确必要升级；禁用阈值不影响其他独立规则。
- [ ] 模型升级由显式能力档位比较。约束生效而现有路线与建议路线缺少可比较档位时，保留有效当前路线并解释原因；不能按名称、价格或同供应商关系猜测升级。
- [ ] 切换当回合成功完成计为第一个保持回合，下一个完整用户回合计为第二个，默认第三个回合开始可降级。工具 step 不独立计数，取消或失败不计完成；必要升级不受保持回合数限制。
- [ ] 保持计数基于实际已执行路线与完整 turn 的完成记录，可在重新加载后重建，不由 Jev 建议次数或内存中临时计数决定。
- [ ] 在同一用户 turn 内坚持既有路线，规则只决定新 turn 的选模；规则阻止模型切换不等于禁止以后由 03 提供的同模型思考强度调整。
- [ ] 缓存证据按会话及具体 provider/model 保存，只采用已报告的缓存读取、未缓存输入及证据时间；缺失为未知，不能把 HTTP 成功或未报告命中量视为真实命中。
- [ ] 启用缓存感知时，将相关证据加入已有分类 state，让足够胜任的当前模型得到保留偏好；预算仍覆盖完整 state，不因加入缓存字段超出分类材料上限。显式阈值和保持规则仍由插件执行，不交给 Jev 自行遵守。
- [ ] 关闭缓存感知移除缓存软偏好，但长度阈值和保持回合数继续生效。新会话不继承其他会话的证据，失去相关性或无法确认的证据记为未知；不承诺下一次一定命中，不假设跨模型共享 KV cache。
- [ ] 可验证的上下文窗口与输入模态仍是独立要求，目标模型需容纳输入并留出输出空间；不能通过额外裁剪执行历史达成切换。没有兼容候选时采用可用原路径或明确报告不能路由。
- [ ] 用户可看到建议模型、实际模型、输入规模及估算标识、阈值或保持规则的阻止原因。原因来自实际规则结果，只有实际生效后才展示为已执行，不改写稳定提示前缀。
- [ ] 真实 Loader 组合从保存设置和发送用户输入验证最终出站模型，而非仅测试比较函数。覆盖阈值下方／相等／上方、禁用、未知规模、两种超限策略、必要升级、不可比较档位和保持计数。
- [ ] 测试覆盖缓存字段缺失、真实命中与零命中的区别、跨会话隔离、相关性失效、恢复保持计数和预算不溢出；补充阈值阻止切换的无密钥会话回放及设置界面证据。适用类型、构建与配置检查通过。

## Scope and handoff

- 不依赖 03 的思考强度适配或高级故障恢复；使用 01 已有回合、配置、实际路线和完成记录完成本票验收。
- 本票负责为路由提供缓存证据和规则解释；04 负责独立控制完整展示／记录及汇总真实验证证据，不重复实现计量语义。
- 不实现跨模型缓存迁移、可调缓存证据有效期、价格表或最低节省比例。
